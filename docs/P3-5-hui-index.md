# P3-5 章回小说回目索引（多篇验证）

| 项 | 值 |
|---|---|
| 日期 | **2026-11-03** |
| 样本 | 《四大名著》影印合订本，前 1600 页（5291 页全书） |
| 结果 | **132 个回目段**，标题取自页眉、逐段核对；检测到 1 个"附录"插入 |
| 成本 | 页眉带 OCR **0.55 s/页**（1600 页 ≈ 15 分钟） |
| 意义 | 第一次在真实数据上跑到"一书多篇"（此前二十四史都是一卷一篇） |

---

## 1. 结论

竖排史书的篇名靠"第X"标题页，章回小说没有"卷"，回目页眉每页都印着——所以换了判据：**页眉标题变化即回目边界**。

前 1600 页得到 132 段：

| 段 | 页范围 | 说明 |
|---|---|---|
| 回1–回100 | p50–约 p1278 | 《西游记》 |
| 回1–回26 | p1279–1599 | 《水浒传》（检测到回号从 1 重新开始，但分界晚 7 段） |

标题示例（与通行本逐一核对）：

```
#1  p50   灵根育孕源流出 心性修持大道生
#2  p62   悟彻菩提真妙理 断魔归本合元神
#3  p76   四海千山皆拱伏 九幽十类尽除名
#9  p142  附录 陈光蕊赴任逢灾 江流僧复仇报本
#10 p154  袁守诚妙算无私曲 老龙王拙计犯天条
```

## 2. 方法

1. 每页只 OCR **页眉带**（y 3%–15%，dpi 80）：0.55 s/页，整页 OCR 是 6 s/页；
2. 页眉里有回目标题（"灵根育孕源流出心性修持大道生"），相邻页标题相同即同一回；
3. 用 difflib 相似度 0.45 合并 OCR 噪声差异；单页异写不算新回（看一眼下一页再切）；
4. 回号优先用页眉上的"第X回"（OCR 常把"第/九/回"拆成三行，先拼再匹配）；没有回号的段按顺序编号；
5. **附录检测**：页眉出现"附"/"录"的段标记为附录、不占回号（《西游记》陈光蕊附录正好插在回8与回9之间，不处理会让后面所有回号偏移 1）。

## 3. 验证

- 回1–9 标题与通行本一致（含回9 前的"陈光蕊"附录）；
- 回10 起回号与页眉印刷号一致（p154 页眉"第九回"→ 我们的 #10 是"袁守诚"，即印刷回 9）；
- 水浒段：p1303 起"史大郎夜走华阴县 鲁提辖拳打镇关西"（水浒 第3回）标题正确；
- 每回 10–14 页，无空洞（132 段连续覆盖 p50–1599）。

## 4. 限制

- **过切**：西游实际 100 回，切出 106 段（+6%）。原因是少数页的页眉缺失或严重异写，被当成新回；
- **分书晚 7 段**：水浒开头几回页眉没有印回号，检测不到"回到 1"，导致边界落在第 107 段而非第 100 段；
- 只扫了前 1600/5291 页（全书含四部小说）；索引**没有写入 sidecar 的 toc 表**（半本索引会让页图浏览显示"没有章回的页"）；
- 回目标题是 OCR 文本，个别字有误（"大阐"应为"大闹"）；
- 这套判据要求每页都有页眉；无页眉的影印本要改用别的方法。

## 5. 复现

```
python eval/p3/novel_hui_ocr.py --pdf "<四大名著.pdf>" --pages 1-1600 \
    --band "0.03,0.0,1.0,0.15" --dpi 80 --out out/hui.jsonl
python eval/p3/build_hui_segments.py --ocr out/hui.jsonl --threshold 0.45 --out out/hui-index.json
```

## 6. 续跑（A：全本收尾，部分完成）

已把 OCR 推到 **2745/5291 页**，并把切分参数收紧（单段 <4 页视为 OCR 抖动，并回上一段），结果：

| 部 | 回 | 页范围 | 说明 |
|---|---:|---|---|
| 西游记 | 101 | 50–1302 | 实际 100 回；末段多出的 1 段是水浒回1被并入 |
| 水浒传 | 106 | 1303–2633 | 末段多出的 1 段是三国回1被并入 |
| 三国演义（未命名） | 8 | 2634–2738 | 页眉只有 8 回被读到 |

三处限制不变：换书边界**晚一回**（下一部的回1 因为页眉没印"第一回"而被并进上一部）、未跑完全书、未落库。

续跑与收尾：

```powershell
# 1) 续跑剩余页（已完成的页会自动跳过）
python eval/p3/novel_hui_ocr.py --pdf "<四大名著.pdf>" --pages 1601-5291 \
    --band "0.03,0.0,1.0,0.15" --dpi 80 --out out/hui.jsonl
# 2) 重新切分（书名可按部指定）
python eval/p3/build_hui_segments.py --ocr out/hui.jsonl --threshold 0.45 \
    --names "1=西游记,2=水浒传,3=三国演义,4=红楼梦" --out out/hui-index.json
```

修边界的两条路：a) 每部开头 OCR 首页书名（本轮已用 p2 / p1276 验证可行）；b) 在"回号大幅回落"处强制切分，而不是等"回到 1"。

## 7. 对主线的意义

- 证明了"一书多篇"的切分链路（回目页眉 → 分段 → 附录/编号）是成立的，不再是只有单测覆盖；
- 与二十四史的卷/篇索引共用同一张 `toc` 表结构（`level=1` 书、`level=2` 篇/回），页图浏览前端不用改；
- 若要正式收进馆藏，需要：跑完 5291 页（约 50 分钟）、把每部书的书名也从页眉 OCR 出来、修过切。
