备选教学路线：借角色，不借自治

多 Agent、TraceBack、dsh-teacher、dsh-openmaic 逐条评估；主干仍是“单模型 + 确定性状态机 + sidecar”。

路线结论理由
多 Agent
Planner/Diagnoser/Tutor		只借角色误差放大、状态多源、泄漏面扩大、成本 ×3；P1-0 单模型已 SR 100%
TraceBack
LangGraph+Milvus+LlamaIndex		参考架构Milvus 对 167k 过重；LangGraph 与状态机双源；只借诊断报告/路径图
dsh-teacherP4 借件FSRS/gap/quiz 可借；要求 DSH rc.6+（当前 rc.3）；无 RAG/PDF/`view`
dsh-openmaicP4 UI只做呈现层；依赖 open.maic.chat 云服务，数据出境，内容不保证忠于原文

多 Agent 的具体判断

  • Planner 每轮跑 → 路径抖动；改离线课程图（概念 DAG）。
  • Diagnoser 自由文本 → 不可回归；改约束 JSON（判定 + 误区 + 置信度），状态机决定是否采信。
  • Tutor 仍单模型；Diagnoser 不看 `answer_key`。
  • 若必须多 Agent：supervisor 是确定性状态机，Agent 只是工具，禁止自由 handoff。
一句话：P1-0 单模型 + 显式摘要已 50 轮 SR 100%、未引用 0/50；多 Agent 没有证据超过它，却确定增加状态源与攻击面。

PTC：计算编排器，不是计算引擎

模型写 run_code，代码调用工具；SymPy/NumPy/Mathematica/LEAN 仍由 sidecar 执行。

场景选择
单题求导/积分/解方程直接 compute_python
多步推导 / 参数扫描 / 批量PTC
学生答案验证（解析→等价→反例）PTC
LEAN 编译（分钟级）job + 轮询，PTC 只提交
逐轮苏格拉底决策状态机，不用 PTC
P2-8（8 h）：10 道题对比直接调用 vs PTC；正确率 10/10、逃逸/泄漏 0、延迟 ≤ +20%、token 省 ≥30%。

六条护栏

  1. 只调白名单门面工具；禁止直连 DB/文件/网络。
  2. sidecar 仍是最终沙箱；`view` 与子进程限制不可绕过。
  3. post-execute 标泄漏/未引用；hint<4 剥离最终答案。
  4. 代码 + 依赖版本 + 种子写凭证；禁止无种子随机。
  5. 输出设上限；大结果落 artifact。
  6. 子调用写 tool/ptc-dispatch；canary 验证零泄漏。
0.2.1-rc.3 是否默认启用 run_code 未验证；P2-8 先探针，未启用就退回直接调用。
