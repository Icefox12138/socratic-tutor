## 1. 结论

P3-3 只在每个卷边界 ±2 页里找篇名，前提是"一卷一篇"。这一轮换成**全页右栏扫描**（右 42%、上 62% 的版面带），一次 OCR 同时拿到：

- 卷眉（"史記卷二"/"三國志卷十"）→ 卷边界；
- 篇名（"夏本紀第二"/"荀彧荀攸賈詡傳第十"）→ 篇起点。

**C1 复现 7/7 篇，并且把 P3-3 错标的卷界改正了**：卷二真正的篇名页是 p67（P3-3 记成 p71，因为卷眉在 p71 才第一次被识别到）。卷七也回到 313–358（P3-3 是 314–356）。

## 2. 判别规则（为什么不用"字更大"）

实测过宽度阈值，不可靠：篇名"五帝本紀第一"框宽 46，同页卷眉"史記卷一"框宽 48——卷眉比篇名还宽。真正稳定的是**行的形态**：

| 信号 | 规则 |
|---|---|
| 短行 | 整行 ≤12 字，且匹配 `(本紀\|世家\|列傳\|傳\|書\|表\|志)第X` |
| 结尾干净 | 序号之后不能跟 `：:.。…·`——目錄行是"春申君列傳第十八："，正文篇名止于序号 |
| 序号递增 | 同一卷内篇的"第X"必须严格递增，且与上一篇至少隔 3 页（排除目錄页连续罗列） |
| 归属 | 就近归卷：距某卷起点 ≤6 页即归该卷（卷眉会漏掉卷首几页，不能只靠包含关系） |

换了一本书、换了"傳第X"的写法，检测仍然成立；第 11 篇的尾字丢失是 OCR 层面的问题，不是切分逻辑。

## 5. 关于"一卷多篇"

本馆藏的二十四史点校本**没有一卷多篇**：纪传体每卷一个篇名，多人合传也是一个篇（如"袁張涼國田王邴管傳第十一"）。所以这条无法在真实数据上验证，只能：

- `toc.merge_pian` 已支持一卷多个篇行（篇范围按下一个篇起点切，末篇到卷末），有单测 `test_multiple_pian_in_one_volume` 覆盖（19–29、30–70 两段）；
- 真实的多篇卷要等章回小说（本馆藏没有）或史记表/书（实测也是一卷一篇）。

## 6. 限制

- S2 只扫了前 140 页（验证用），没有落库；
- 篇名靠 OCR，短标题更易错（S2 卷11 丢字）；
- 带宽裁切（0.58–1.0 × 0.03–0.65）按中华书局版式定，换版式要调；
- 目錄页噪声靠"结尾标点 + 连续罗列"两条规则压住，遇到不带标点的目錄仍可能漏。

## 7. 复现

```
python eval/p3/render_pages.py --book C1 --dpi 130
python eval/p3/vertical_title_ocr.py --book C1 --png-dir out/C1_pages --out out/C1_titles.jsonl --crop "0.58,0.03,1.0,0.65"
python eval/p3/build_index.py --book C1 --toc out/C1-toc.json --band out/C1_titles.jsonl --out out/C1-index.json
```

`build_index.py` 也支持 `--headers`（卷眉单独一遍）或完全从带宽里推卷（`--band` 单独用）。
